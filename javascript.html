PARTIE 1

Les bases modernes

Quatre modules pour poser une syntaxe JS propre et actuelle — pas celle des tutoriels de 2015 encore pleins de var et de fonctions callback partout.

Partie 1 · Module 01

Pourquoi JavaScript

JavaScript a une particularité qu'aucun autre langage ne partage vraiment : c'est le seul langage qui tourne nativement dans tous les navigateurs, sans rien installer. Avec Node.js, il tourne aussi côté serveur — ce qui permet à une seule personne de tenir tout un projet web, front et back, avec un seul langage.

Tu connais déjà Python, ce qui te donne une vraie longueur d'avance : les deux sont des langages dynamiquement typés, avec une syntaxe lisible. Les différences qui comptent le plus au début :

PythonJavaScript
Indentation obligatoireAccolades { }, l'indentation est une convention, pas une règle
print("Bonjour")console.log("Bonjour")
def ma_fonction():function maFonction() {} ou const maFonction = () => {}
Un seul type d'égalité (==)=== (égalité stricte, à toujours préférer) vs == (avec conversion de type, à éviter)
Tourne où Python est installéTourne nativement dans n'importe quel navigateur

Le point le plus important pour bien démarrer : utilise toujours === et jamais ==. Ce dernier convertit silencieusement les types avant de comparer ("5" == 5 vaut true), une source classique de bugs difficiles à repérer.

Partie 1 · Module 02

Variables et types

JavaScript a trois façons historiques de déclarer une variable — une seule règle à retenir en 2027 : n'utilise jamais var. Cette ancienne syntaxe a un comportement de portée (scope) déroutant, source de bugs, entièrement remplacé par let et const.

Mot-cléUsage
constLa valeur ne sera jamais réassignée — ton choix par défaut, dans 90 % des cas
letLa valeur changera au cours du programme (un compteur, par exemple)
varÀ éviter — présent uniquement dans du code ancien que tu pourrais croiser

Les types primitifs principaux : string (texte), number (tous les nombres, pas de distinction int/float comme en Python), boolean, null (absence volontaire de valeur) et undefined (valeur jamais définie).

Les template literals (avec des backticks, pas des guillemets)

const prenom = "Karim";
const age = 29;
console.log(`${prenom} a ${age} ans.`);   // interpolation directe, sans + partout

Un vrai gain de lisibilité comparé à l'ancienne concaténation avec + — l'équivalent des f-strings de Python (f"{prenom} a {age} ans").

Partie 1 · Module 03

Fonctions modernes

Deux syntaxes principales cohabitent en JS moderne. La déclaration classique :

function carre(n) {
  return n * n;
}

Et la fonction fléchée (arrow function), plus concise, très utilisée en JS moderne :

const carre = (n) => n * n;               // retour implicite si une seule expression
const addition = (a, b) => { return a + b; };  // avec accolades, retour explicite requis

Les fonctions peuvent avoir des paramètres par défaut — l'équivalent des valeurs par défaut Python :

const saluer = (nom = "candidat") => `Bonjour ${nom} !`;
console.log(saluer());          // "Bonjour candidat !"
console.log(saluer("Rmili"));   // "Bonjour Rmili !"
Une nuance pour plus tard, à retenir dès maintenant

Les fonctions fléchées ne redéfinissent jamais this — elles héritent du contexte qui les entoure. Ce détail semble abstrait maintenant, mais il évite un piège classique qu'on rencontrera concrètement au module 12, sur les événements.

Partie 1 · Module 04

Conditions et boucles

if / else if / else et l'opérateur ternaire fonctionnent comme en Python, à la syntaxe près :

const statut = stock > 0 ? "en stock" : "épuisé";

Pour les boucles, JavaScript moderne privilégie for...of pour parcourir un tableau — l'équivalent quasi direct du for x in liste de Python :

const outils = ["Playwright", "Postman", "k6", "GitHub"];
for (const outil of outils) {
  console.log(outil);
}
Piège classique à éviter

for...in parcourt les clés d'un objet, pas les valeurs d'un tableau — l'utiliser sur un tableau donne des résultats surprenants (les index sous forme de texte). Pour un tableau, c'est toujours for...of ; for...in est réservé aux objets.

Partie 2 · Module 06

Objets et destructuring

Un objet JavaScript ressemble beaucoup à un dictionnaire Python — des paires clé/valeur :

const candidature = {
  entreprise: "NovaCart",
  poste: "Testeur QA junior",
  statut: "entretien",

console.log(candidature.entreprise);   // accès par point
console.log(candidature["poste"]);     // accès par crochets, utile si la clé est dynamique

Le destructuring extrait directement des valeurs dans des variables — très utilisé en JS moderne pour éviter les accès répétitifs :

const { entreprise, statut } = candidature;
console.log(entreprise, statut);   // "NovaCart" "entretien"

const [premier, deuxieme] = ["Playwright", "Postman"];  // pareil pour les tableaux

Partie 2 · Module 07

Spread, rest et JSON

L'opérateur spread (...) copie le contenu d'un tableau ou d'un objet — indispensable pour modifier une donnée sans muter l'original, une bonne pratique en JS moderne :

const candidature = { entreprise: "NovaCart", statut: "envoyée" };
const miseAJour = { ...candidature, statut: "entretien" };
// candidature reste inchangée, miseAJour est une nouvelle copie modifiée

const outils = ["Playwright", "Postman"];
const plusOutils = [...outils, "k6"];   // ["Playwright", "Postman", "k6"]

Le même symbole, utilisé dans une déclaration de fonction, s'appelle rest et regroupe un nombre variable d'arguments :

const additionner = (...nombres) => nombres.reduce((a, b) => a + b, 0);
console.log(additionner(1, 2, 3, 4));   // 10

JSON : le format d'échange universel

Déjà croisé dans le cours API — en JavaScript, la conversion est native, sans librairie :

const texte = JSON.stringify(candidature);   // objet → texte
const objet = JSON.parse(texte);             // texte → objet

PARTIE 3

Asynchrone

Trois modules sur ce qui distingue le plus JavaScript de Python : sa façon de gérer les opérations qui prennent du temps sans jamais bloquer le programme entier.

Partie 3 · Module 08

L'event loop

JavaScript s'exécute sur un seul fil d'exécution (single-threaded) — contrairement à certains langages, il ne peut pas faire deux choses en même temps dans le même programme. Pourtant, il ne se bloque jamais en attendant qu'une page charge ou qu'une réponse réseau arrive. Le mécanisme qui rend ça possible s'appelle l'event loop (boucle d'événements).

Le principe simplifié : le code synchrone s'exécute immédiatement, dans l'ordre. Une opération asynchrone (comme setTimeout, ou un appel réseau) est "mise de côté" et ne s'exécute qu'une fois que tout le code synchrone est terminé — même avec un délai de zéro milliseconde.

Voir l'explication

C'est exactement ce mécanisme qui permet à une page web de rester réactive (cliquable, scrollable) pendant qu'elle attend une réponse réseau en arrière-plan.

Partie 3 · Module 09

Les Promises

Une Promise représente une valeur qui n'est pas encore disponible, mais qui le sera — soit avec succès (résolue), soit avec une erreur (rejetée). C'est l'outil qui structure proprement le code asynchrone, plutôt que d'empiler des callbacks (l'ancienne approche, illisible au-delà de deux niveaux).

Une fonction simulée, qui imite un appel réseau vers NovaCart

function verifierStock(idArticle) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (idArticle === 42) {
        resolve({ nom: "Casque audio", stock: 12 });
      } else {
        reject(new Error("Article introuvable"));
      }
    }, 600);
  });
}
verifierStock(42)
  .then(article => console.log(`En stock : ${article.nom} (${article.stock})`))
  .catch(erreur => console.log("Erreur :", erreur.message));

Partie 3 · Module 10

async / await

async/await réécrit exactement la même logique que les Promises, mais avec une syntaxe qui se lit comme du code synchrone — beaucoup plus proche de ce que tu connais déjà en Python. C'est la syntaxe à privilégier en JS moderne dès que c'est possible.

async function afficherStock(idArticle) {
  try {
    const article = await verifierStock(idArticle);
    console.log(`En stock : ${article.nom} (${article.stock})`);
  } catch (erreur) {
    console.log("Erreur :", erreur.message);
  }
}

afficherStock(42);

await ne peut être utilisé qu'à l'intérieur d'une fonction marquée async — c'est ce mot-clé qui indique à JavaScript "cette fonction peut mettre en pause son exécution ici, sans bloquer le reste du programme".

Erreur fréquente

Oublier await devant un appel qui retourne une Promise ne provoque pas d'erreur immédiate — la variable contient simplement l'objet Promise en attente, pas sa valeur résolue, ce qui provoque des bugs silencieux plus loin dans le code. Si une valeur ressemble à Promise { <pending> } dans tes logs, c'est le signe classique d'un await manquant.

Bac à sable

(pas encore exécuté)

Partie 4 · Module 11

Sélectionner et manipuler

Le DOM (Document Object Model) est la représentation d'une page web que JavaScript peut lire et modifier — chaque balise HTML devient un objet manipulable.

const carte = document.querySelector("#carte");        // un seul élément
const boutons = document.querySelectorAll(".btn");     // tous les éléments correspondants

carte.textContent = "Nouveau texte";     // change le texte, sans risque
carte.innerHTML = "<strong>Gras</strong>"; // insère du HTML — dangereux avec du contenu non fiable (XSS, cours QA module 24)
Réflexe sécurité

innerHTML avec un contenu qui vient d'un utilisateur (un commentaire, un champ de formulaire) est une porte ouverte à une injection XSS — exactement le type de faille qu'OWASP ZAP recherche dans le cours QA (module 24). Par défaut, préfère toujours textContent sauf besoin explicite d'insérer du HTML de confiance.

Partie 4 · Module 12

Les événements

addEventListener écoute un événement (clic, saisie, soumission...) sur un élément et exécute une fonction en réponse. Une technique importante quand plusieurs éléments similaires doivent réagir pareil : la délégation d'événements — écouter sur le parent plutôt que sur chaque enfant individuellement, pratique quand des éléments sont ajoutés dynamiquement.

document.querySelector("#liste").addEventListener("click", (evenement) => {
  if (evenement.target.matches(".supprimer")) {
    evenement.target.closest("li").remove();
  }
});

evenement.target est l'élément précis qui a réellement été cliqué — utile pour savoir exactement quoi faire quand l'écouteur est posé sur un parent commun plutôt que sur chaque bouton.

Formulaires et validation

Un formulaire déclenche l'événement submit, qu'on intercepte avec preventDefault() pour empêcher le rechargement complet de la page (le comportement par défaut du navigateur) et gérer la soumission en JavaScript.

document.querySelector("#formulaire").addEventListener("submit", (evenement) => {
  evenement.preventDefault();
  const email = document.querySelector("#email").value;
  if (!email.includes("@")) {
    console.log("Email invalide");
    return;
  }
  console.log("Formulaire valide :", email);
});

Quatre modules pour finir de moderniser ta pratique — classes, modules, TypeScript et les outils que tu verras dans n'importe quelle offre d'emploi front-end en 2027.

Partie 5 · Module 14

Classes et closures

Les classes JavaScript ressemblent beaucoup aux classes Python — un constructeur, des méthodes :

class Candidature {
  constructor(entreprise, statut) {
    this.entreprise = entreprise;
    this.statut = statut;
  }
  resume() {
    return `${this.entreprise} — ${this.statut}`;
  }
}

const c = new Candidature("NovaCart", "entretien");
console.log(c.resume());

Les closures

Une closure est une fonction qui "se souvient" des variables de son contexte de création, même après que ce contexte a normalement terminé son exécution — un concept propre à JS (et quelques autres langages), sans équivalent direct aussi naturel en Python.

function creerCompteur() {
  let total = 0;
  return function () {
    total++;
    return total;
  };
}

const compter = creerCompteur();
console.log(compter());  // 1
console.log(compter());  // 2 — "total" a été mémorisé entre les deux appels

Partie 5 · Module 15

Modules ES6

Les modules permettent de séparer le code en plusieurs fichiers, chacun exportant ce qu'il veut rendre disponible ailleurs — indispensable dès qu'un projet dépasse un seul fichier. Ce mécanisme a besoin d'un vrai environnement de build ou d'un serveur pour fonctionner (pas dans un simple bac à sable comme ci-dessus), donc ce module reste volontairement en lecture : le comprendre suffit pour l'instant, tu le pratiqueras concrètement dans un projet réel avec l'outillage du module 17.

export function creerCandidature(entreprise, statut) {
  return { entreprise, statut };
}

export const STATUTS_POSSIBLES = ["envoyée", "entretien", "refus", "accepté"];

Partie 5 · Module 16

Introduction à TypeScript

TypeScript ajoute un système de types à JavaScript — le code doit être compilé (transformé) en JavaScript classique avant de s'exécuter, ce qui veut dire qu'il ne peut pas tourner directement dans un bac à sable navigateur comme les modules précédents. Ce module reste donc en lecture, pour comprendre la logique avant, si tu le souhaites, de l'installer plus tard dans un vrai projet.

Le même code, en JavaScript puis en TypeScript

// JavaScript — aucune garantie sur le type des paramètres
function calculerTotal(prix, quantite) {
  return prix * quantite;
}

// TypeScript — l'erreur ci-dessous est détectée AVANT l'exécution
function calculerTotal(prix: number, quantite: number): number {
  return prix * quantite;
}
calculerTotal(49.99, "deux");  // ❌ erreur de compilation : "deux" n'est pas un number

L'intérêt concret : une erreur de type se révèle en JavaScript classique seulement à l'exécution — parfois en production, au pire moment. En TypeScript, elle est détectée immédiatement, avant même de lancer le code, directement dans l'éditeur.

Faut-il l'apprendre maintenant ?

Pas dans l'urgence : tout le JavaScript de ce cours reste valide et utile tel quel. Mais sache que beaucoup d'offres d'emploi front-end en 2026-2027 mentionnent TypeScript aux côtés de JavaScript — une fois les bases JS solides (ce cours), passer à TypeScript demande surtout d'apprendre à annoter les types, pas de tout réapprendre.

Question

Pourquoi calculerTotal(49.99, "deux") est-il détecté comme une erreur par TypeScript, mais s'exécuterait silencieusement (avec un résultat incorrect, NaN) en JavaScript classique ?

Voir la correction

TypeScript vérifie les types avant l'exécution (à la compilation) — quantite: number interdit explicitement de passer une chaîne de caractères, et l'erreur apparaît immédiatement dans l'éditeur. En JavaScript classique, sans cette vérification, 49.99 * "deux" s'exécute et retourne NaN (Not a Number) — un bug qui ne se révèle souvent qu'au moment où le résultat est utilisé plus loin.

function afficherCandidatures() {
  const liste = document.querySelector("#liste");
  liste.innerHTML = "";
  if (candidatures.length === 0) {
    liste.innerHTML = "<li>Aucune candidature pour l'instant</li>";

Partie 6 · Module 19

CRUD complet et persistance

On assemble maintenant les quatre opérations CRUD (Create, Read, Update, Delete) et la persistance — sans elle, toute candidature ajoutée disparaîtrait au rechargement de la page. localStorage stocke des données directement dans le navigateur, au format texte — donc toujours via JSON.stringify/JSON.parse (module 7).

function sauvegarder() {
  localStorage.setItem("candidatures", JSON.stringify(candidatures));
}

function charger() {
  const donnees = localStorage.getItem("candidatures");
  return donnees ? JSON.parse(donnees) : [];
}

function ajouterCandidature(entreprise, poste, statut) {
  candidatures.push({ id: Date.now(), entreprise, poste, statut, date: new Date().toISOString() });
  sauvegarder();
  afficherCandidatures();
}

function supprimerCandidature(id) {
  candidatures = candidatures.filter(c => c.id !== id);
  sauvegarder();
  afficherCandidatures();
}

Date.now() comme identifiant est une astuce simple et fiable pour un projet de cette taille : deux candidatures ne peuvent quasiment jamais être créées à la même milliseconde exacte, ce qui suffit à garantir un identifiant unique sans avoir besoin d'un vrai système de base de données.
