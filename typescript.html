NIVEAU 1

Démarrer avec TypeScript

Trois modules pour écrire, compiler et comprendre ton tout premier code TypeScript — sans supposer que tu connais déjà JavaScript en profondeur.

Niveau 1 · Module 01

Pourquoi TypeScript, et comment l'installer

TypeScript est un sur-ensemble de JavaScript : tout code JavaScript valide est déjà du TypeScript valide. Ce qu'il ajoute, c'est un système de types vérifié avant l'exécution — le compilateur (tsc) refuse de générer le fichier .js final si un type ne correspond pas, plutôt que de laisser l'erreur se produire chez un utilisateur ou pendant un test.

Installer TypeScript et compiler un premier fichier

CommandeCe qu'elle fait
npm install -D typescriptInstalle le compilateur TypeScript dans le projet
npx tsc --initGénère un fichier tsconfig.json avec les options par défaut
npx tscCompile tous les fichiers .ts du projet en .js, selon le tsconfig
npx ts-node fichier.tsExécute un fichier .ts directement, sans étape de compilation séparée (pratique pour tester vite)

bonjour.ts

function saluer(nom: string): string {
  return `Bonjour, ${nom} !`;
}

console.log(saluer('Amina'));
console.log(saluer(42)); // Erreur de compilation : 42 n'est pas une string
Ce que ça change concrètement

En JavaScript pur, saluer(42) s'exécuterait sans broncher et produirait un résultat probablement faux ("Bonjour, 42 !"). En TypeScript, l'éditeur souligne l'erreur avant même que tu lances le programme, et tsc refuse de compiler.

Voir la correction

  return a + b;

Niveau 1 · Module 02

Types primitifs et annotations

TypeScript propose une annotation pour chaque type primitif de JavaScript, plus quelques types propres au typage statique.

TypeExempleRemarque
stringlet nom: string = 'Amina';Guillemets simples, doubles ou template strings, indifféremment
numberlet age: number = 27;Un seul type numérique — pas de distinction int/float comme en Python
booleanlet actif: boolean = true;—
null / undefinedlet valeur: string | null = null;Détaillé au module 10
(inféré)let ville = 'Paris';Sans annotation, TypeScript déduit string tout seul à partir de la valeur

L'inférence de type : ne pas tout annoter

Annoter let ville: string = 'Paris'; est redondant : TypeScript infère déjà string à partir de la valeur assignée. La règle pratique : annoter les paramètres de fonction et les retours (module 3), laisser l'inférence faire le reste pour les variables locales évidentes.

let annees = 5;          // inféré : number
let pays = 'France';     // inféré : string
annees = 'cinq';          // Erreur : 'cinq' n'est pas assignable à number
Exercice

Déclare trois variables sans les annoter explicitement — un nom, un prix, une disponibilité en stock — puis vérifie mentalement (ou dans ton éditeur) le type que TypeScript infère pour chacune.

Voir la correction 
let nomProduit = 'Casque audio';  // inféré : string
let prix = 59.9;                  // inféré : number
let enStock = true;               // inféré : boolean

Aucune annotation nécessaire ici — TypeScript lit la valeur littérale et en déduit le type le plus précis possible.

Niveau 1 · Module 03

Fonctions typées

Une fonction typée annonce, avant même d'être lue, ce qu'elle attend et ce qu'elle promet de retourner — utile pour soi-même six mois plus tard, et indispensable pour quiconque appelle cette fonction sans en avoir lu le corps.

Paramètres, retour, valeurs par défaut, paramètres optionnels

function calculerRemise(prix: number, pourcentage: number = 10): number {
  return prix - (prix * pourcentage) / 100;
}

function formaterNom(prenom: string, nom?: string): string {
  return nom ? `${prenom} ${nom}` : prenom;
}

calculerRemise(100);        // pourcentage par défaut : 10 -> 90
calculerRemise(100, 20);    // -> 80
formaterNom('Yanis');        // -> "Yanis"
formaterNom('Yanis', 'B.');  // -> "Yanis B."

nom?: string signifie « ce paramètre peut être omis » — son type réel à l'intérieur de la fonction est string | undefined, pas juste string.

Les fonctions fléchées, typées de la même façon

const multiplier = (a: number, b: number): number => a * b;

const estMajeur = (age: number): boolean => age >= 18;
Toujours annoter le retour d'une fonction publique

TypeScript peut inférer le type de retour tout seul, mais l'annoter explicitement sur une fonction utilisée ailleurs dans le projet évite qu'un changement accidentel du corps de la fonction modifie silencieusement son contrat.

Exercice

Écris une fonction estPrixValide(prix: number): boolean qui retourne true si le prix est strictement positif, puis une fonction appliquerTva(prix: number, taux?: number): number où taux vaut 20 par défaut si non fourni.

Voir la correction 
function estPrixValide(prix: number): boolean {
  return prix > 0;
}

function appliquerTva(prix: number, taux: number = 20): number {
  return prix * (1 + taux / 100);
}

appliquerTva(100);      // -> 120
appliquerTva(100, 5.5); // -> 105.5

Niveau 2 · Module 04

Tableaux, tuples et objets typés

Un tableau JavaScript peut mélanger n'importe quel type ; un tableau TypeScript, non — sauf si on le décide explicitement.

Tableaux

let notes: number[] = [12, 15, 9, 18];
let noms: Array<string> = ['Ana', 'Léo']; // syntaxe équivalente à string[]

notes.push(20);   // OK
notes.push('20'); // Erreur : '20' n'est pas assignable à number

Tuples : un tableau de longueur et de types fixes

let coordonnee: [number, number] = [48.85, 2.35];
let statutHttp: [number, string] = [404, 'Not Found'];

coordonnee = [1, 2, 3]; // Erreur : trop d'éléments pour ce tuple

Un tuple est utile quand l'ordre et le nombre d'éléments ont un sens précis — contrairement à un tableau classique, qui suppose une liste homogène de longueur variable.

Objets typés inline

let utilisateur: { nom: string; age: number; actif: boolean } = {
  nom: 'Sami',
  age: 31,
  actif: true
};

utilisateur.age = 'trente-deux'; // Erreur de type

Ce type inline devient vite pénible à répéter — le module 5 introduit une façon de le nommer une fois pour toutes.

Niveau 2 · Module 05

Interfaces et type aliases

Plutôt que de répéter { nom: string; prix: number } partout, on lui donne un nom réutilisable. TypeScript propose deux syntaxes pour ça : interface et type.

interface Produit {
  nom: string;
  prix: number;
  enStock: boolean;
}

type ProduitAlias = {
  nom: string;
  prix: number;
  enStock: boolean;
};

function afficher(p: Produit): string {
  return `${p.nom} — ${p.prix} €`;
}
SituationChoix conseilléPourquoi
Forme d'un objet (le cas le plus courant)interfacePeut être étendue plus tard (extends), messages d'erreur souvent plus lisibles
Union, tuple, type calculétypeinterface ne peut pas représenter une union de types

Propriétés optionnelles et lecture seule

interface Utilisateur {

Niveau 2 · Module 06

Union types et literal types

Une union type dit « cette valeur peut être de tel type OU de tel autre » — plus honnête qu'un any quand la variabilité est en réalité limitée à quelques cas connus.

let identifiant: string | number;
identifiant = 'user-42'; // OK
identifiant = 42;        // OK aussi
identifiant = true;      // Erreur : boolean n'est pas dans l'union

Literal types : restreindre à des valeurs précises

let statut: 'en_attente' | 'validee' | 'annulee';
statut = 'validee';  // OK
statut = 'en cours'; // Erreur : cette chaîne n'est pas l'une des trois valeurs autorisées

function changerStatut(s: 'en_attente' | 'validee' | 'annulee') {
  console.log(`Nouveau statut : ${s}`);
}

C'est nettement plus strict qu'un simple string : le compilateur refuse toute valeur en dehors de la liste exacte, y compris une faute de frappe.

Exercice

Déclare un type Role restreint aux valeurs 'client', 'admin' et 'support', puis une fonction peutSupprimerUnProduit(role: Role): boolean qui retourne true uniquement pour 'admin'.

Voir la correction 
type Role = 'client' | 'admin' | 'support';

function peutSupprimerUnProduit(role: Role): boolean {
  return role === 'admin';
}
Niveau 2 · Module 07

Enums

Un enum nomme un ensemble fixe de constantes liées entre elles — une alternative aux literal types du module 6, utile quand le groupe de valeurs a une identité propre plutôt que d'être juste « une des chaînes possibles ici ».

enum StatutCommande {
  EnAttente,
  Validee,
  Expediee,
  Annulee
}

let statut: StatutCommande = StatutCommande.Validee;
console.log(statut); // 1 (chaque membre reçoit un nombre croissant à partir de 0)

Enum à valeurs de chaîne — souvent préférable

enum StatutCommande {
  EnAttente = 'EN_ATTENTE',
  Validee = 'VALIDEE',
  Expediee = 'EXPEDIEE',
  Annulee = 'ANNULEE'
}

console.log(StatutCommande.Validee); // 'VALIDEE' — bien plus lisible dans un log ou une base de données
Enum ou union de literal types ?

Beaucoup d'équipes en 2026 préfèrent une union de literal types (module 6) à un enum : pas de code JavaScript généré en plus, comparaison directe avec de simples chaînes venant d'une API. Réserve l'enum aux cas où le regroupement sous un même nom (StatutCommande.Validee) apporte une vraie clarté.

Exercice

Définis un enum à valeurs de chaîne NiveauLog avec Info, Avertissement, Erreur, puis une fonction formaterLog(niveau: NiveauLog, message: string): string.

Voir la correction 
enum NiveauLog {
  Info = 'INFO',
  Avertissement = 'AVERTISSEMENT',
  Erreur = 'ERREUR'

function formaterLog(niveau: NiveauLog, message: string): string {

Niveau 3 · Module 08

Classes : constructeur, propriétés, méthodes

class Produit {
  nom: string;
  prix: number;

  constructor(nom: string, prix: number) {
    this.nom = nom;
    this.prix = prix;
  }

  appliquerRemise(pourcentage: number): number {
    return this.prix - (this.prix * pourcentage) / 100;
  }
}

const stylo = new Produit('Stylo', 2.5);
console.log(stylo.appliquerRemise(10)); // 2.25

Raccourci : déclarer les propriétés dans le constructeur

class Produit {
  constructor(public nom: string, public prix: number) {}

  appliquerRemise(pourcentage: number): number {
    return this.prix - (this.prix * pourcentage) / 100;
  }
}
// Strictement équivalent à la version précédente, en plus court.

Niveau 3 · Module 09

Héritage, modificateurs d'accès, interfaces implémentées

Héritage avec extends

class Utilisateur {
  constructor(public nom: string, public email: string) {}

  seConnecter(): string {
    return `${this.nom} s'est connecté.`;
  }
}

class Administrateur extends Utilisateur {
  constructor(nom: string, email: string, public permissions: string[]) {
    super(nom, email);
  }

  supprimerProduit(id: string): string {
    return `${this.nom} a supprimé le produit ${id}.`;
  }
}

const admin = new Administrateur('Léa', 'lea@novacart.fr', ['supprimer', 'modifier']);
console.log(admin.seConnecter()); // méthode héritée

Modificateurs d'accès

ModificateurAccessible depuis
publicPartout (par défaut si omis)
privateUniquement à l'intérieur de la classe elle-même
protectedLa classe elle-même et ses classes filles (extends)

Une classe qui implémente une interface

interface Notifiable {
  envoyerNotification(message: string): void;
}

class ServiceEmail implements Notifiable {
  envoyerNotification(message: string): void {
    console.log(`E-mail envoyé : ${message}`);
  }
}
// `implements` force la classe à fournir exactement les méthodes promises par l'interface.

Écrire du TypeScript robuste

Jusqu'ici, l'essentiel de la syntaxe. Ces quatre modules sont ceux qui distinguent un code qui compile d'un code qui empêche réellement des bugs d'exister.

Niveau 4 · Module 10

null, undefined et le mode strict

Sans le mode strict, TypeScript autorise null et undefined à peu près partout — ce qui annule une bonne partie de l'intérêt du typage. Le mode strict ("strict": true dans tsconfig.json) change ça.

// Sans strictNullChecks
let email: string = null; // autorisé — dangereux

// Avec strictNullChecks (recommandé, activé par "strict": true)
let email: string = null; // Erreur : null n'est pas assignable à string
let email2: string | null = null; // OK — il faut le dire explicitement

Optional chaining ?. et nullish coalescing ??

interface Utilisateur {
  nom: string;
  adresse?: { ville: string };
}

function afficherVille(u: Utilisateur): string {
  return u.adresse?.ville ?? 'Ville inconnue';
}
// ?.  : n'accède à .ville que si adresse existe, sinon renvoie undefined sans planter
// ??  : remplace seulement si la valeur est null ou undefined (contrairement à ||, qui remplacerait aussi 0 ou '')
Pourquoi ?? et pas ||

quantite || 10 remplacerait aussi une quantité valide de 0 par 10 — un vrai bug silencieux dans un panier. quantite ?? 10 ne remplace que null/undefined, donc 0 reste 0.

Exercice

Avec l'interface Utilisateur ci-dessus, écris une fonction compterCaracteresVille(u: Utilisateur): number qui retourne la longueur du nom de la ville, ou 0 si l'adresse n'existe pas — sans jamais planter.

Voir la correction 
function compterCaracteresVille(u: Utilisateur): number {
  return u.adresse?.ville.length ?? 0;
}
Niveau 4 · Module 11

Type narrowing et type guards

Quand une variable peut être de plusieurs types (union, module 6), TypeScript « rétrécit » son type au fil du code, à condition de le vérifier explicitement au bon endroit.

function afficherId(id: string | number): string {
  if (typeof id === 'string') {
    return id.toUpperCase(); // TypeScript sait ici que id est une string
  }
  return id.toFixed(0);      // et ici, que id est un number
}

instanceof et in

class Chien { aboyer(): string { return 'Wouf'; } }
class Chat { miauler(): string { return 'Miaou'; } }

function faireDuBruit(animal: Chien | Chat): string {
  if (animal instanceof Chien) return animal.aboyer();
  return animal.miauler();
}

interface Voiture { roues: number; }
interface Bateau { moteurHorsBord: boolean; }

function decrire(v: Voiture | Bateau): string {
  if ('roues' in v) return `${v.roues} roues`;
  return 'Un bateau';
}

Un type guard personnalisé

function estString(valeur: unknown): valeur is string {
  return typeof valeur === 'string';
}

function traiter(valeur: unknown) {
  if (estString(valeur)) {
    console.log(valeur.toUpperCase()); // valeur est bien typée string ici
  }
}
Exercice

Écris une fonction longueur(valeur: string | string[]): number qui retourne la longueur de la chaîne, ou le nombre d'éléments si c'est un tableau, en utilisant Array.isArray() pour le narrowing.

Voir la correction 
function longueur(valeur: string | string[]): number {
  if (Array.isArray(valeur)) {
    return valeur.length;
  }
  return valeur.length; // fonctionne aussi sur une string
}

Array.isArray() est lui-même un type guard intégré à TypeScript — il rétrécit l'union exactement comme typeof ou instanceof.

any, unknown, never : bien choisir

TypeCe qu'il signifieÀ utiliser quand
anyDésactive complètement la vérification de typeIdéalement jamais — c'est une porte de sortie, pas un outil

function parser(brut: string): unknown {
  return JSON.parse(brut);
}

const donnees = parser('{"nom":"Amina"}');
donnees.nom; // Erreur : il faut vérifier la forme de 'donnees' avant

function echouerToujours(message: string): never {
  throw new Error(message);
}

never dans un switch exhaustif

type Statut = 'en_attente' | 'validee' | 'annulee';

function libelle(s: Statut): string {
  switch (s) {
    case 'en_attente': return 'En attente';
    case 'validee': return 'Validée';
    case 'annulee': return 'Annulée';
    default:
      const exhaustif: never = s; // si un nouveau statut est ajouté au type sans être géré ici,
      return exhaustif;           // cette ligne ne compile plus -> l'oubli est détecté à la compilation
  }
}
Exercice

Écris une fonction parserJson(brut: string): unknown, puis une fonction estUtilisateurValide(valeur: unknown): valeur is { nom: string } qui vérifie que la valeur est un objet avec une propriété nom de type string.

Voir la correction 
function parserJson(brut: string): unknown {
  return JSON.parse(brut);
}

function estUtilisateurValide(valeur: unknown): valeur is { nom: string } {
  return (
    typeof valeur === 'object' &&
    valeur !== null &&
    'nom' in valeur &&
    typeof (valeur as { nom: unknown }).nom === 'string'
  );
}
Niveau 4 · Module 13

Discriminated unions

Plutôt qu'un type flou avec des champs tous optionnels, on donne à chaque forme possible un champ commun — souvent status ou type — qui permet au compilateur de savoir exactement quels champs existent dans chaque branche.

type ReponseApi =
  | { status: 'success'; donnees: { id: string; nom: string } }
  | { status: 'erreurValidation'; champs: string[] }
  | { status: 'erreurServeur'; code: number };

function traiterReponse(reponse: ReponseApi): string {
  switch (reponse.status) {
    case 'success':
      return `Reçu : ${reponse.donnees.nom}`;
    case 'erreurValidation':
      return `Champs invalides : ${reponse.champs.join(', ')}`;
    case 'erreurServeur':
      return `Erreur serveur ${reponse.code}`;
  }
}

Dans chaque case, TypeScript sait automatiquement quels champs sont disponibles — impossible d'écrire reponse.champs dans la branche 'success', le compilateur le refuse.

Exercice

Modélise le résultat d'une tentative de paiement avec une union discriminée à trois branches : 'approuve' (avec un numeroTransaction: string), 'refuse' (avec une raison: string), 'enAttente' (sans champ additionnel). Écris une fonction qui affiche un message adapté à chaque cas.

Voir la correction 
type ResultatPaiement =
  | { statut: 'approuve'; numeroTransaction: string }
  | { statut: 'refuse'; raison: string }
  | { statut: 'enAttente' };

function messagePaiement(resultat: ResultatPaiement): string {
  switch (resultat.statut) {
    case 'approuve':
      return `Paiement approuvé (transaction ${resultat.numeroTransaction})`;
    case 'refuse':
      return `Paiement refusé : ${resultat.raison}`;
    case 'enAttente':
      return 'Paiement en attente de confirmation';
  }
}
NIVEAU 5

TypeScript avancé

Ce que la plupart des cours pour débutants n'abordent jamais : utiliser le système de types comme un outil de conception, sur des cas qu'on rencontre vraiment en construisant un vrai projet.

Niveau 5 · Module 14

Generics

Sans generics, une fonction ou une classe réutilisable pour plusieurs types finit par être copiée-collée une fois par type, ou perd son typage en passant par any. Les generics permettent d'écrire cette logique une seule fois, pour n'importe quel type.

Une fonction générique, simple

function premierElement<T>(tableau: T[]): T | undefined {
  return tableau[0];
}

premierElement<number>([1, 2, 3]);        // -> number | undefined
premierElement<string>(['a', 'b']);       // -> string | undefined
premierElement([true, false]);            // T inféré automatiquement : boolean

Une fixture réutilisable, écrite une seule fois

function creerFixture<T>(
  creer: () => Promise<T>,
  supprimer: (ressource: T) => Promise<void>
) {
  let ressource: T;
  return {
    async setup() { ressource = await creer(); return ressource; },
    async teardown() { await supprimer(ressource); }
  };
}

const fixtureUtilisateur = creerFixture<Utilisateur>(
  () => api.creerUtilisateurDeTest(),
  (u) => api.supprimerUtilisateur(u.id)
);
// Même implémentation, réutilisable pour n'importe quel type de ressource.

Contraindre un generic avec extends

function afficherNom<T extends { nom: string }>(item: T): string {
  return item.nom; // autorisé : T est garanti d'avoir au moins .nom
}

afficherNom({ nom: 'Casque', prix: 59 }); // OK
afficherNom({ prix: 59 });                // Erreur : il manque 'nom'

TypeScript fournit une boîte à outils de types dérivés d'un type existant, sans jamais le réécrire à la main.

Architecturer son code : erreurs typées, retry, tooling

Ce module rassemble ce qui distingue un projet TypeScript avec une vraie discipline d'ingénierie d'un projet qui compile juste par chance.

Erreurs typées plutôt qu'un try/catch à l'aveugle

type Resultat<T> =
  | { ok: true; valeur: T }
  | { ok: false; erreur: string };

async function tenterConnexion(email: string, motDePasse: string): Promise<Resultat<Session>> {
  const reponse = await api.post('/connexion', { email, motDePasse });
  if (reponse.status !== 200) {
    return { ok: false, erreur: `Connexion refusée (${reponse.status})` };
  }
  return { ok: true, valeur: reponse.data as Session };
}

const resultat = await tenterConnexion(email, motDePasse);
if (!resultat.ok) {
  throw new Error(`Échec : ${resultat.erreur}`);
}
const session = resultat.valeur; // garanti d'exister ici

Contrairement à une exception, impossible d'oublier de gérer l'échec par erreur : le compilateur refuse d'accéder à .valeur sans avoir vérifié .ok d'abord.

Un retry générique et typé

async function avecRetry<T>(
  action: () => Promise<T>,
  tentatives = 3,
  delaiMs = 500
): Promise<T> {
  let derniereErreur: unknown;
  for (let i = 0; i < tentatives; i++) {
    try {
      return await action();
    } catch (erreur) {
      derniereErreur = erreur;
      await new Promise((resolve) => setTimeout(resolve, delaiMs * (i + 1)));
    }
  }
  throw derniereErreur;
}

Exercice — MISSION : la méthode ajouter qui refuse l'implicite

Écris la méthode ajouter de la classe Panier. Elle doit retourner une union discriminée à trois branches : { statut: 'ajoute'; article: Article }, { statut: 'stockInsuffisant' }, { statut: 'quantiteInvalide' } — jamais lever d'exception pour un cas prévisible.

Voir une correction possible 
interface Article {
  id: string;
  nom: string;
  prix: number;
  quantite: number;
}

type ResultatAjout =
  | { statut: 'ajoute'; article: Article }
  | { statut: 'stockInsuffisant' }
  | { statut: 'quantiteInvalide' };

class Panier {
  private articles: Article[] = [];

  ajouter(article: Article, stockDisponible: number): ResultatAjout {
    if (article.quantite <= 0) {
      return { statut: 'quantiteInvalide' };
    }
    if (article.quantite > stockDisponible) {
      return { statut: 'stockInsuffisant' };
    }
    this.articles.push(article);
    return { statut: 'ajoute', article };
  }

  total(): number {
    return this.articles.reduce((somme, a) => somme + a.prix * a.quantite, 0);
  }
}

Chaque branche de ResultatAjout force l'appelant à gérer explicitement l'échec — exactement le principe du module 16, appliqué ici à un vrai cas d'usage plutôt qu'à un exemple isolé.

Ce que ce projet prouve

N'importe qui peut écrire un panier qui fonctionne. Ce qui se voit sur un dépôt GitHub, c'est si chaque cas d'échec prévisible est modélisé dans les types eux-mêmes, plutôt que découvert au premier bug en production.
